# 架构设计与模块说明

## 1. 架构概述

项目采用单文件前端原型架构。
HTML、CSS、JavaScript 均位于 final_1025.html 中，无业务后端。

当前模块为逻辑划分，尚未拆分为独立代码文件；
部分功能通过后续脚本包装或覆盖原函数实现。

浏览器界面
  ↓
事件处理、角色判断、业务状态转换
  ↓
localStorage：合同、模板、审批、消息、日志
IndexedDB：上传原件、扫描件、审批附件

外部依赖：通过 CDN 加载 PDF.js 4.10.38。
项目未调用大模型 API、真实短信或电子签章 API。

## 2. 模块规格

| 模块 | 输入与处理 | 输出 |
|---|---|---|
| 账号与权限 | 演示账号、角色和合同归属判断 | 对应菜单、可见合同及操作 |
| 合同编辑 | 模板或上传正文、主体及业务字段 | 草稿、正文预览、版本记录 |
| 文档识别 | PDF、DOCX、TXT、MD；本地规则提取 | 正文、字段候选及核对提示 |
| 审批调度 | 分派人、审批意见、退回目标、附件 | 审批记录、下一节点与通知 |
| 紧急任务 | 非标合同优先级及紧急理由 | 紧急标记、列表优先排序 |
| 模拟签署 | 当前合同版本、链接令牌、模拟验证 | 签署记录、状态更新与归档 |
| 合同归档 | 完成签署记录或人工确认的扫描件 | 汇总查询、预览、下载、CSV |
| 留痕与通知 | 业务操作与状态变化 | 消息、操作日志、版本差异 |

## 3. 核心数据

Contract：
合同编号、归属人、类型、状态、版本、业务字段、正文、
优先级、原件引用、承办法务、审批记录、签署记录和归档信息。

Template：
模板编号、正文、字段定义、版本、启停状态和历史记录。

Approval：
审批人、节点、合同版本、结论、意见、退回位置和附件引用。

File：
文件 ID、名称、类型、大小及 Blob 内容。

## 4. 主要流程

标准双方协议：
草稿 → 免审批 → 甲方签署 → 乙方签署 → 归档。

标准单方函件：
填写 → 甲方签署 → 单方完成并归档。

非标协议：
草稿 → 法务主管分派或自行审批 → 法务专员通过 →
财务通过 → 甲方签署 → 乙方签署 → 归档。

退回：
支持退回提交人或上一环节，清除相关审批通过标记。
业务修改正式合同后生成新版本，再重新提交。
审批修改附件仅作为参考，不自动替换正式正文。

## 5. 业务角色分工

| 角色 | 职责 |
|---|---|
| 业务经理 | 创建、修改、提交、撤回合同，办理模拟签署 |
| 法务主管 | 调度、改派、自行处理法务审批，管理模板 |
| 法务专员 | 审批本人承办合同，提出修改意见 |
| 财务审批人 | 核对财务信息，审批或退回 |
| 模拟乙方 | 在独立签署页面完成模拟确认 |

## 7. 风险与后续优化

- 前端权限仅用于演示，正式系统需增加服务端认证和授权。
- 合并重复函数及补丁，统一流程状态转换和归档逻辑。
- 修复跨窗口编辑丢失问题，增加草稿保存和合同级冲突检测。
- 统一模板配置与实际合同正文。
- 正式签署需接入真实服务，并隔离外部签署页与内部账号。
- 增加自动化流程测试；本地日志不作为防篡改审计记录。
